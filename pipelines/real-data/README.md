# Real Data Pipeline (Go)

Real pipeline implementation with channels and worker pools:

`collector -> analyzer -> validator -> auto-rewriter -> validator -> publisher`

No fake/simulated dataset is generated by the pipeline. Input is fetched from a real source URL and all validation goes through the real Clisonix audit script.

## Run

```bash
cd pipelines/real-data
go run . \
  --source-url "http://clisonix-dr-albana:8040/api/v1/medical/content/your-article-id" \
  --domain "medical" \
  --article-id "your-article-id" \
  --publisher-source "dr_albana" \
  --error-rate "0.004" \
  --publish-mode "blog_publisher" \
  --publish-endpoint "http://localhost:8010/api/v1/publish"
```

## Required flags

- `--source-url`: real HTTP source to collect from
- `--domain`: domain tag
- `--article-id`: article ID required for `blog_publisher` mode
- `--error-rate`: used by `scripts/audit_medical_gen_layers.py`
- `--publish-endpoint`: real API endpoint for publish step

## Optional flags

- `--notify-endpoint`: webhook for alerts/events
- `--publisher-source`: `blerina` or `dr_albana` (used in `blog_publisher` mode)
- `--publish-mode`: `blog_publisher` (default) or `raw`
- `--python-bin`: python executable path for audit script
- `--audit-script`: path to `audit_medical_gen_layers.py`
- worker counts and timeout flags

## Stage statuses

Validation returns:

- `PASS`
- `SOFT_FAIL` (typically fixable doc gaps)
- `HARD_FAIL` (blocked)

Only `PASS` and fixed `SOFT_FAIL` are routed to publish.

## Blog Publisher compatibility

When `--publish-mode=blog_publisher`, publisher sends exactly this payload to `/api/v1/publish`:

```json
{
  "article_id": "...",
  "source": "dr_albana"
}
```

This matches `services/blog_publisher/main.py` `PublishRequest` contract directly.
